# ISO/IEC 25010 제품 품질 모델 — 요구사항 분류표

품질 요구사항은 아래 특성(characteristic)과 부특성(sub-characteristic) 중 하나로 분류한다. **적용한 판을 명세 머리에 적는다.** 이 표는 요지이며 표준 원문 번역이 아니다. 정확한 정의는 사용자가 가진 표준 문서로 확인한다.

## 2023판 (9개 특성)

| 특성 | 부특성 | 이 프로젝트(임베디드 C)에서 쓰는 측정 예 |
|---|---|---|
| Functional suitability | Functional completeness, Functional correctness, Functional appropriateness | 요구 기능 구현 비율, 출력 오차 한계 |
| Performance efficiency | Time behaviour, Resource utilization, Capacity | 응답 시간·WCET, ROM/RAM/스택 사용량, 동시 처리 가능 신호 수 |
| Compatibility | Co-existence, Interoperability | 다른 ECU와의 메시지 형식 일치, 공유 자원 간섭 |
| Interaction capability (2011판: Usability) | Appropriateness recognizability, Learnability, Operability, User error protection, User engagement, Inclusivity, User assistance, Self-descriptiveness | 진단 메시지 명확성, 오조작 방지 |
| Reliability | Faultlessness, Availability, Fault tolerance, Recoverability | 고장 없이 동작하는 시간, 신호 소실 시 동작 유지, 리셋 후 복구 시간 |
| Security | Confidentiality, Integrity, Non-repudiation, Accountability, Authenticity, Resistance | 접근 제어, 메시지 인증, 데이터 무결성 검사 |
| Maintainability | Modularity, Reusability, Analysability, Modifiability, Testability | 순환 복잡도 10 이하, 모듈 결합도, 테스트 커버리지 |
| Flexibility (2011판: Portability) | Adaptability, Scalability, Installability, Replaceability | 다른 MCU로의 이식 시 수정 범위, 파라미터화 |
| Safety (2023판 신규) | Operational constraint, Risk identification, Fail safe, Hazard warning, Safe integration | **기능 안전 요구는 SAF로 별도 문서에 쓴다.** 이 특성은 상위 분류 표시용 |

## 2011판 (8개 특성)

Functional suitability, Performance efficiency, Compatibility, Usability, Reliability, Security, Maintainability, Portability.

## 분류 규칙

1. 요구사항은 **가장 가까운 특성 하나**에 분류한다. 두 특성에 걸치면 요구를 쪼갠다.
2. 측정 기준 없는 품질 요구는 쓰지 않는다. 기준은 `수치 + 측정 방법 + 조건` 셋이 모두 있어야 한다.
3. 적용 판단: 9개(또는 8개) 특성 전부를 한 번씩 검토하고, 요구가 없는 특성은 명세에 `해당 없음 — 사유`로 남긴다.
4. Maintainability는 이 저장소의 개발 규칙(순환 복잡도, 커버리지)과 겹친다. 그 수치를 REQ-Q로 올리려면 CLAUDE.md "소스코드 품질"의 기준과 같은 값을 쓴다.
