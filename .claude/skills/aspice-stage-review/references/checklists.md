# 산출물별 리뷰 체크리스트

산출물마다 체크리스트가 하나씩 있고, 항목은 **A-SPICE 기본 프랙티스(BP)**와 **이 프로젝트의 규칙(CLAUDE.md, 스킬)**에서 나왔다. 기준 수치는 CLAUDE.md가 우선한다. 둘이 다르면 CLAUDE.md를 따르고 이 파일을 고치도록 지적한다.

- BP 번호는 Automotive SPICE PAM 3.1 기준이다. 심사 판을 확인해 다르면 `BP` 열을 고친다(원문은 사용자가 가진 표준 문서로 확인한다).
- **확인 방법** 약어: `도구` = 명령을 직접 실행해 판정, `전수` = 대상 전부를 대조, `읽기` = 내용을 읽고 판단.
- 판정은 `적합 / 부적합 / 해당 없음(사유) / 미확인`.

## 산출물 ↔ 체크리스트 대응

| 단계 | 산출물 | 체크리스트 | 작성 스킬 |

| SWE.5 | `docs/swe5/integration-test-spec.md` | CL-ITS | integration-test-coverage |

## 체크리스트 개발·개선

체크리스트는 한 번 쓰고 끝나지 않는다. 다음 경우에 항목을 추가·수정한다.

1. **새 산출물 유형**이 생기면 그 산출물의 체크리스트를 만든다.
   - 해당 프로세스의 A-SPICE 기본 프랙티스를 BP별로 훑어 "이 산출물에서 무엇이 있어야 BP를 만족했다고 말할 수 있는가"를 항목으로 쓴다.
   - 이 프로젝트의 규칙(CLAUDE.md, 작성 스킬의 규칙)을 항목으로 옮긴다. 도구가 판정할 수 있는 것은 `도구`로 표시하고 명령을 적는다.
   - 항목은 **예/아니오로 판정 가능**해야 한다. "충분히 명확한가"처럼 주관적인 항목은 "모호한 표현이 없다"처럼 관찰 가능한 형태로 바꾼다.
2. **리뷰에서 체크리스트에 없던 종류의 결함**을 발견하면 그 결함을 잡는 항목을 해당 체크리스트에 추가한다(리뷰 기록에 "체크리스트 개선" 항목으로 남긴다).
3. **CLAUDE.md나 작성 스킬의 규칙이 바뀌면** 같은 변경에서 체크리스트도 함께 고친다.
4. 항목 ID는 재사용하지 않는다(삭제한 번호는 비워 둔다).
5. 체크리스트 변경은 별도 커밋으로 하고, 어느 리뷰에서 비롯됐는지 커밋 본문에 적는다.
