# A-SPICE 산출물 리뷰

이 저장소의 **모든 산출물**은 이 스킬로 리뷰하고, 리뷰를 통과해야 다음 단계로 넘어간다. 리뷰는 A-SPICE의 요건(각 프로세스의 기본 프랙티스, SUP.1 품질 보증)에 따라 **산출물별 체크리스트**를 기준으로 하며, 리뷰 기록은 심사의 증적이다.

체크리스트는 `references/checklists.md`에 있다. 산출물 ↔ 체크리스트 대응표가 맨 위에 있다.

## 원칙

- **모든 산출물**: 코드뿐 아니라 요구사항, 설계서, 테스트 명세·코드·결과서, 추적성 결과까지 리뷰한다. 산출물이 체크리스트 대응표에 없으면 먼저 체크리스트를 만든다(체크리스트 문서의 "체크리스트 개발·개선").
- **체크리스트가 기준**: 모든 항목에 판정을 남긴다. 체크리스트에 없는 이유로 통과·불통과를 정하지 않는다(필요하면 체크리스트에 항목을 추가한다).
- **독립성**: 산출물을 만든 에이전트(세션)가 스스로 리뷰하지 않는다. `stage-reviewer` 서브에이전트가 수행한다.
- **리뷰어는 고치지 않는다**: 지적만 하고 수정은 작성자가 한다. 리뷰어가 쓰는 파일은 리뷰 기록뿐이다.
- **근거 있는 지적만**: 지적마다 위치(파일·줄·ID)와 근거(체크리스트 항목 ID 또는 CLAUDE.md 조항)를 적는다. 근거를 댈 수 없는 것은 `의견`이다.
- **도구가 판정하는 것은 직접 실행한다**: 체크리스트 `확인` 열이 `도구`인 항목은 작성자의 보고를 믿지 않고 리뷰어가 컨테이너에서 실행한다.

## 절차

1. **대상 확정**: 단계(SWE.x), 이 단계의 산출물 전체, 상위(입력) 산출물, 변경 범위(`git diff develop...HEAD --stat`). 대응표로 산출물마다 적용할 체크리스트를 정한다.
2. **도구 실행**: 해당 산출물의 `도구` 항목을 모두 실행한다. 컨테이너 도구는 `docker compose run --rm dev tools/run.sh <명령>`, 추적성은 `python3 .claude/skills/requirements-analysis/scripts/trace_check.py --docs docs --src src --stage <단계>`.

   | 산출물 | 실행할 도구 |
   |---|---|
   | 요구사항·안전 요구사항 | `trace_check.py --stage swe1` |
   | 아키텍처 | `trace_check.py --stage swe2` |
   | 상세 설계 | `trace_check.py --stage swe3` |
   | 소스 코드 | `tools/run.sh format`, `build`, `rules`, `static`, `complexity`, `trace_check.py --stage swe3-impl` |
   | 단위 테스트 | `tools/run.sh testdocs`, `unit`, `trace_check.py --stage swe4` |
   | 통합 테스트 | `tools/run.sh testdocs`, `integration`, `trace_check.py --stage swe5` |
   | SW 검증 테스트 | `system-test-case-generator`의 `build_workbook.py` 검증 결과 |

3. **체크리스트 적용**: 산출물별로 체크리스트의 **모든 항목**에 `적합 / 부적합 / 해당 없음(사유) / 미확인`을 판정한다. `전수` 항목은 표본이 아니라 대상 전체를 대조한다(ID 목록을 grep으로 뽑아 비교).
4. **지적 분류**:

   | 등급 | 기준 | 게이트 영향 |
   |---|---|---|
   | `중대` (부적합) | 요구사항 누락·오해, 추적성 단절, 품질 기준 미달(커버리지·복잡도·Cppcheck·반환 규칙), 인터페이스 규칙 위반, 안전 관련 결함, 테스트가 실제로 검증하지 않음 | 0건이어야 통과 |
   | `경미` (부적합) | 문서 불일치, 명명·주석 규칙 위반, 불명확한 서술 | **0건이어야 통과.** 중대와 같이 모두 조치해야 다음 단계로 넘어간다 |
   | `의견` | 근거 조항이 없는 개선 제안 | 영향 없음 |

5. **체크리스트 개선**: 리뷰 중 체크리스트에 없던 종류의 결함을 발견했으면, 항목을 추가할 것을 기록에 남긴다(리뷰어는 체크리스트 파일을 직접 고치지 않고 "체크리스트 개선 제안" 표에 쓴다. 반영은 작성자가 별도 커밋으로 한다).
6. **기록 작성**: `docs/reviews/<단계>-review-<회차>.md`(예: `SWE.2-review-1.md`). 재리뷰는 회차를 올리고 이전 지적마다 조치 확인 결과를 적는다.
7. **판정**: `통과`(부적합 0건 = 중대 0건이고 경미 0건, 미확인 0건), `불통과`(부적합이 하나라도 있거나 미확인이 있음). 조건부 통과는 없다.
8. **조치와 재리뷰**: 불통과이면 작성자가 모든 부적합을 조치하고 재리뷰를 요청한다. 재리뷰(회차 +1)에서 이전 지적의 조치를 도구와 산출물로 직접 다시 확인하고, 조치로 새로 생긴 문제도 같은 기준으로 본다. 부적합이 0건이 될 때까지 반복하며, 통과 판정 전에는 다음 단계로 넘어가지 않는다.

## 리뷰 기록 양식

```markdown
# <단계> 리뷰 <회차>회

- 일자: YYYY-MM-DD
- 대상 커밋: <해시>   입력(상위 산출물): <경로>
- 리뷰어: stage-reviewer
- 판정: 통과 | 불통과

## 리뷰한 산출물과 적용 체크리스트
| 산출물 | 경로 | 체크리스트 | 항목 수 | 적합 | 부적합 | 해당 없음 | 미확인 |
|---|---|---|---|---|---|---|---|

## 도구 결과
| 도구 | 명령 | 결과(판정 줄) |
|---|---|---|

## 체크리스트 판정 (산출물별)
### <산출물> — <체크리스트 ID>
| 번호 | 판정 | 비고 |
|---|---|---|

## 지적 사항
| ID | 등급 | 산출물:위치 | 내용 | 근거(체크리스트 ID) | 조치(작성자 기입) |
|---|---|---|---|---|---|
| R-<단계>-<회차>-01 | 중대 | src/x.c:42 | ... | CL-SRC-02 | |

## 이전 지적 조치 확인 (재리뷰일 때)

## 체크리스트 개선 제안
| 체크리스트 | 제안 항목 | 계기가 된 결함 |
|---|---|---|
```

## 보고

호출한 쪽에 판정(통과/불통과), 산출물별 항목 판정 요약(적합/부적합/해당 없음/미확인 수), 등급별 지적 수, 리뷰 기록 경로, 중대 지적 한 줄 요약 목록, 체크리스트 개선 제안을 돌려준다. 도구를 실행하지 못했으면 그 사실을 쓰고 해당 항목을 `미확인`으로 둔다. 미확인이 있으면 `통과`로 판정하지 않는다.
